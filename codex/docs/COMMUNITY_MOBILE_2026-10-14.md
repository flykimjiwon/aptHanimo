# 한바퀴 · 모바일과 주민 제보

2026-10-14. 주력 `/` 안에서 이어 개발했다. 목표는 **단지 산책 + 현장 확인 + 주민 자료로 계속 보완되는 지도**다. 비교판을 새로 만들지 않았다.

## 동작하는 범위

| 흐름 | 구현 |
|---|---|
| 모바일 산책 | 320px 작은 화면·짧은 가로 화면 레이아웃, 지도 안 방향 버튼, 터치 취소·키보드 해제, 스크롤 중에도 보이는 수첩 진입 |
| 다시 해볼 일 | 동 살펴보기·목적지 도착·친구 꾸미기 3개 탐험 도장. 단지별 이 브라우저에 저장하며 실제 방문 인증과 구분 |
| 임장 수첩 | 현장 확인 5항목·메모. 명시적 저장, 실패 표시, 단지별 분리. 기존 생활권 수첩은 별도 보존 |
| 주변 확인 | 기존 OSM 장소·출처·자료 날짜. 현재 영업이나 장단점을 새로 확인했다고 쓰지 않음 |
| 주민 이야기 | 좋았던 점·아쉬운 점·지도/성능 개선·사진 자료·사진 요청. 위치·주제·관찰일·닉네임·본인 표기 관계를 함께 접수 |
| 공동 자료 | 같은 서버의 SQLite에 보관. 검토 대기 자료는 공개 목록과 사진 URL에서 제외. 서버를 재시작해도 유지 |
| 지속 개선 | 운영자가 공개/비공개/반영 완료 상태와 설명을 기록. 게시글 문제 신고·작성자 철회·접수증 복원 |

닉네임 접수를 기본으로 구현했다. 로그인·실거주 인증·회원간 댓글·알림은 아직 없다. 공개된 의견도 사실 인증이나 검증된 주민 신분을 뜻하지 않는다. 가짜 초기 후기·사진·인원수를 넣지 않는다.

## 실행과 저장

```sh
cd codex
bun install --frozen-lockfile
bun run build
bun start
```

`http://localhost:5178/`. 실제 API는 `bun start`가 제공한다. Vite 개발 서버만 실행하거나 정적 파일만 배포하면 주민 제보 API가 없으므로 서버 연결 오류가 표시된다. 사진 처리용 `sharp`는 서버 의존성이고 브라우저 번들에는 포함되지 않는다.

- `HANBAKWI_DATA_DIR`: 영속 데이터 디렉토리. 기본 `codex/.community`; DB·WAL·이미지를 Git/정적 배포에 포함하지 않는다.
- `HANBAKWI_PORT`, `HANBAKWI_HOSTNAME`: 기존 서버 설정. 로컬 한정은 `127.0.0.1`.
- `HANBAKWI_PUBLIC_ORIGIN`: HTTPS 프록시 뒤에서는 실제 공개 origin을 설정한다. 예: `https://town.example`. 클라이언트의 임의 `X-Forwarded-For`를 신뢰하지 않는다. 현재 접속 IP당 쓰기 제한이므로 프록시 환경에서는 모든 요청이 같은 IP로 묶일 수 있다. 외부 운영 전 프록시 쪽 속도 제한과 전달 정책을 정한다.
- 수첩: `hanbakwi-village-field-v1:<complex>`. 접수증: `hanbakwi-village-receipts-v1`. 기존 `hanbakwi-*` 생활권 기록을 읽거나 마이그레이션하지 않는다.
- 접수증 token은 작성자 조회·철회 권한이다. 공개/로그/스크린샷에 넣지 않는다. 브라우저 저장 실패 시 화면의 비공개 접수증을 보관하고 수첩의 복원 기능으로 다시 넣을 수 있다. 수첩을 닫았다 다시 열면 미전송 초안이 유지되지만, 새로고침 전에는 저장/복사가 필요하다.

## 운영자가 자료를 반영하는 순서

명령은 **서버의 비공개 파일에 접근할 수 있는 운영자만** 실행한다. 공개 관리자 API나 브라우저용 관리자 비밀번호는 만들지 않았다.

```sh
bun run community:moderate list
# 100건씩; 마지막 항목의 cursor 이전 페이지
bun run community:moderate list 123
bun run community:moderate photo <id> /private/review/new-photo.webp
bun run community:moderate approve <id> '위치와 촬영 방향을 확인해 관찰 의견으로 공개'
bun run community:moderate reject <id> '개인정보가 보여 비공개 처리. 가린 자료로 다시 접수해 주세요.'
bun run community:moderate resolve <id> '확인한 출입구 표기를 다음 버전에 반영. 변경 근거와 버전 설명'
bun run community:moderate reports
bun run community:moderate backup /private/backups/new-community.sqlite
```

사진은 먼저 열어 얼굴·번호판·호수·제3자 자료 여부를 확인한다. 관찰 의견의 공개와 지도 정본의 변경은 별도다. 출처·촬영일·방향과 현장 자료를 대조하고 정본을 수정한 뒤 테스트/재생성/커밋한다. 그 뒤에만 실제 변경 내용으로 `resolve`를 기록한다. 주민 사진을 AI가 자동으로 사실 확정하거나 좌표 원자료를 덮어쓰지 않는다.

백업은 SQLite `VACUUM INTO`로 일관된 별도 파일을 만들며 기존 경로를 덮어쓰지 않는다. 백업도 비공개 자료다. 운영 시 보관 기간·철회 자료의 백업 만료·복원 담당자를 정한다. `.sqlite` 파일만 실행 중 복사하는 방식은 WAL 기록 누락 가능성이 있으므로 쓰지 않는다.

## 경계와 자원 제한

- 입력은 서버·클라이언트 Zod로 검사. 글은 DOM 텍스트로 이스케이프하며 사진 파일명/원본 메타데이터를 공개하지 않는다.
- 쓰기는 동일 origin에서만 접수. 공개 전 사진 비공개, 작성자 API는64자리 무작위 token의 서버 해시로 확인. token 없이 ID만으로 조회/철회할 수 없다.
- 요청7MiB, 사진6MiB/2천만 화소, JPG·PNG·WebP 정지 영상. HEIC 등은 JPG로 변환 필요. 최대1600px WebP로 재인코딩하며 EXIF/GPS를 제거. 얼굴/번호판을 자동으로 가리는 기능은 없다.
- 사진 처리 동시2개, 접속 IP당 쓰기30회/시간, 게시물5,000개, 저장 사진 합계128MiB. 한도 도달은503으로 명시. 한도는 소규모 파일 기반 운영 기준이며 대규모 부하 검증 결과가 아니다.
- 피드는20건씩, 사진은 지연 로드. 커뮤니티 화면은 첫 진입 때 별도 번들을 로드. 반복 폴링 없음.
- 지도는 정지·화면 밖에서 렌더링하지 않는다. 산책 갱신은60Hz 이내; 탭/뷰포트 복귀 때 지난 시간을 한꺼번에 적용하지 않는다. 기존 섬에도 같은 스케줄러를 적용한다.
- 동 번호의 위치는 카메라·확대·화면 크기·라벨 표시 상태가 바뀔 때만 계산한다. 전체 보기 산책에서 움직이지 않는 라벨을 매 프레임 다시 배치하지 않으며, 친구 표시도 따라가기 중에만 갱신한다.

구현 참고: [Bun SQLite](https://bun.sh/docs/runtime/sqlite), [sharp 입력 제한](https://sharp.pixelplumbing.com/api-constructor/), [sharp 출력·메타데이터](https://sharp.pixelplumbing.com/api-output/). 실제 구현·검증 수치는 이 저장소 코드와 개인 메타 검수 보고를 기준으로 한다.

## 다음 개발과 공개 서비스 조건

1. 실제 iOS Safari·Android Chrome에서 사진 선택/HEIC 변환, 키보드 열림, 세로↔가로 전환, 긴 산책 발열·배터리 측정.
2. 영속 볼륨·HTTPS 도메인·백업 복원·신고 대응 담당을 정해 실제 호스팅에 배포. 현재 로컬 실행·Git 푸시를 인터넷 공개 서비스로 표현하지 않는다.
3. 현재 단지 외곽선 원자료는 연구용 공개 API 응답이며 상용/재배포 권리가 확정된 자료가 아니다(`research/SOURCES.md`, world JSON 출처 메모). 외부 서비스 공개 전 허용 범위 확인 또는 권리 확보된 지도로 교체.
4. 실사용자 피드백으로 로그인·실거주 인증 필요 수준 결정. 계정 복구/권한/개인정보 운영을 포함해 설계하고 댓글·알림·사진 의뢰 진행판을 이어 붙인다.
5. 실제 출입구·계단·경사·주변 장단점의 현장 증거를 수집해 검토. 자료가 없는 길·안전성·접근성을 임의로 확정하지 않는다.

관련 코드: `src/village/{mobile.css,pad.ts,neighborhood.ts}`, `src/island/{frames.ts,view.ts}`, `src/community/`, `src/server/community-*.ts`, `scripts/community-moderate.ts`. 서버 데이터는 생성물이므로 커밋하지 않는다. 검수용 후기는 임시 DB에서만 만들고 철회한다.
