# Codex 수첩 이어가기 · 2026-10-12

기존 저장·삭제·Markdown 내보내기에 **검색, 단지 필터, 목록에서 수정, 저장 장소를 지도에서 선택**하는 흐름을 추가했다. Claude의 비교·기록 흐름을 참고하되 Codex의 장소 ID와 현재 지도 자료를 사용한다.

## 사용자 흐름

1. 장소에서 메모와 직접 확인한 항목을 저장한다.
2. 나의 수첩에서 단지를 고르고 장소·메모·체크 항목을 검색한다. 여러 검색어는 모두 일치해야 한다. 최근 저장한 기록이 먼저 나온다.
3. 기록 수정은 저장 당시의 단지·장소 ID에 묶인다. 현재 월드가 다른 단지여도 기록이 섞이지 않는다. 과거 체크 항목도 보존한다. 저장·취소 후 검색·단지 선택을 유지한다.
4. 지도에서 보기는 필요한 단지와 실내/실외 공간을 열고 목적지를 선택한다. 다음 이동은 사용자가 길안내를 눌러 시작한다. 실제 방문이나 출입 가능을 보증하지 않는다. 다른 단지로 전환할 때는 기존 규칙대로 도보·출발점에서 시작한다.
5. 삭제는 취소를 기본 포커스로 둔 확인 화면을 거친다. 전체 내려받기는 필터와 무관하게 모든 기록을 내보낸다.

## 코드 지도와 계약

| 파일 | 역할 |
|---|---|
| `src/notebook-model.ts` | 기존 ID의 단지/장소 연결, Unicode 정규화 검색, 체크 항목 합집합, 같은 ID 교체 |
| `src/notebook-view.ts` | 목록·필터·편집 화면, HTML 이스케이프, 검색 포커스와 모달 스크롤 |
| `src/notebook.ts` | 입력·수정·저장·삭제 확인·재방문 이벤트와 모달 내부 오류 안내 |
| `src/controller.ts` | 비동기 단지 변경 성공 여부 반환, 없는 POI 차단, 실제 공간·장소 선택 |
| `src/storage.ts` | 기존 v1 스키마 읽기/쓰기, 손상·접근 실패 구분, 쓰기 전 검증 |
| `src/notebook.css` | 기존 paper/ink 규칙의 목록·필터·동작 버튼, 최소44px 입력/버튼 |
| `src/notebook.test.ts` | 새 회귀14건 |

- 저장 키 `hanbakwi-notes-v1`, ID `<complex>:<place>`, 기존 필드는 그대로다. 데이터 이전이나 자동 초기화를 하지 않는다.
- 알 수 없는 ID는 읽기·편집·내보내기를 유지하고 지도 버튼만 비활성화한다. 코드에 있는 장소라도 현재 공간 JSON에 POI가 없으면 단지 전환 전에 거절한다.
- 저장 실패는 편집 내용을 유지하고 모달 안에 표시한다. 손상된 저장 내용은 빈 수첩으로 덮어쓰지 않는다. 500개 초과·1,500자 초과 쓰기를 거절한다.
- 저장된 문자열은 HTML·속성에 넣기 전에 이스케이프한다. 체크 인덱스 대신 체크 문자열을 저장 폼 값으로 사용해 오래된 항목을 유지한다.
- 단지 전환 요청 번호를 유지해 오래된 응답이 최신 요청을 덮지 않는다. 비동기 지도 열기가 끝나도 이미 교체된 수첩 화면을 닫지 않는다.
- 모달은 native dialog를 재사용한다. 화면 전환 시 상단을 보여주고 검색/메모 입력에 포커스를 준다. 검색 중에는 결과 영역만 바꾼다.
