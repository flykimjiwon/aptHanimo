# 한바퀴 V5 · 전체 월드 스타일과 자유 산책 구현 가이드

기준일: 2026-10-12. Codex 독립 구현본. 기존 Claude 프로토타입과 코드·생성 파이프라인을 합치지 않는다. GitHub에서는 `codex/`가 이 앱이며 `prototype/`은 Claude 앱이다.

현재 구현과 자동 검증을 정리한 문서다. V5 실제 브라우저 화면·모바일 터치 QA는 사용자 제어로 넘어간 Ego53의 권한 창이 처리되기 전까지 미검증이다. 기존 버전의 화면 캡처를 V5 검증으로 사용하지 않는다. Git push와 웹 서비스 배포는 별개다.

## 1. 실행하고 체험하기

```sh
cd codex
bun install --frozen-lockfile
bun run build
bun start
```

로컬 단독 작업 폴더에서는 `cd codex` 대신 해당 프로젝트 폴더로 이동한다. 브라우저에서 `http://localhost:5178/`을 연다. 본편은 파일 더블클릭 실행이 아니라 서버 실행이 필요하다. 같은 Wi-Fi 휴대폰에서는 실행 컴퓨터의 LAN IP와 5178 포트를 사용한다.

- 기본 하이베르: `/?complex=haiver`
- 왕십리자이: `/?complex=xi`
- 라체르보: `/?complex=cherbo`
- 현장풍 예: `/?complex=cherbo&character=round-buddy&building=realistic&map=realistic-neighborhood&view=perspective`
- 스타일 비교 실험실: `/style-lab.html`

WASD·방향키·모바일 조이스틱으로 자유 이동한다. 지면을 누르면 해당 지점으로 길을 안내한다. 휠·핀치·확대축소 버튼으로 줌하고, 카메라 회전·따라가기 버튼을 사용할 수 있다. 평면 시점은 북쪽 고정이다. 이동 속도는 1·2·4·8·16배, 기본 2배다. 배속은 체험 이동에만 적용하고 거리와 경로 예상시간 수치를 바꾸지 않는다.

`순간이동`에서 장소를 선택하거나 `지도에서 직접 시작 위치 고르기`를 누른 뒤 땅을 탭한다. 지도 선택 중에는 확대·이동해 원하는 위치를 찾을 수 있다. 취소 버튼이나 Escape로 해제한다. 통행 불가·범위 밖 지점이면 안내하고 원래 위치를 유지한다. 유효한 인근 셀이 16m 안에 있으면 그 셀로 보정한다. 자동차는 도로 규칙을 따른다. 커뮤니티는 자동차·자전거를 도보로 바꾼다. 선택한 장소 카드의 `이곳에서 시작`도 같은 순간이동 기능이다.

`스타일`을 열어 캐릭터·건물·지도·시점을 각각 선택한다. 프리셋 7개, 현재 조합 링크 복사, 브라우저 저장을 제공한다. 실험실의 `이 조합으로 산책하기`는 실제 본편을 해당 스타일·단지·밤 상태로 연다. URL의 유효한 스타일 값이 저장된 값보다 우선하며 잘못된 값은 저장값/기본값으로 돌아간다.

## 2. 구현한 스타일

본편은 **캐릭터 10종 / 건물 11종 / 지도 11종 / 시점 3종**이다. 실험실 갤러리는 기존 각 10종을 유지한다. 본편에 추가한 현장풍 두 종류 때문에 수가 다르다.

| 캐릭터 ID | 형태와 매체 |
|---|---|
| `crew-pixel` | 원래 계단형 PixelCrew 방향별 도트 아틀라스 |
| `round-buddy` | 둥근 몸통의 실제 저폴리 3D 메시, 기본값 |
| `voxel-walker` | 박스 몸통과 블록 발 |
| `paper-scout` | 종이 컷아웃 방향별 고해상도 아틀라스 |
| `ink-friend` | 잉크선 방향별 아틀라스 |
| `plush-crew` | 봉제 몸통과 스티치 메시 |
| `bead-crew` | 구슬을 조합한 입체 몸통 |
| `rubber-hose` | 캡슐 몸통과 가는 팔 |
| `leaf-guide` | 입체 몸통·잎사귀 모자·잎 스카프 |
| `sticker-pop` | 두꺼운 외곽선 스티커 아틀라스 |

6종은 실제 메시이고 4종은 방향별 스프라이트다. 사용자 본인 PixelCrew의 돔·흰 사각 눈·분홍 볼·세 발·노란 스카프 문법을 참조했다. 외부 동명의 캐릭터나 상업 게임 리소스를 가져오지 않았다. 이동한 거리에 맞춰 몸과 발을 움직이며 멈추면 정지 자세로 돌아온다. 혼자·커플·가족 동행과 네 이동수단에도 적용된다.

| 건물 ID | 지도 ID | 표현 |
|---|---|---|
| `soft-isometric` | `soft-village` | 크림 벽·포근한 마을, 기본값 |
| `pixel-blocks` | `pixel-grid` | 분절 밴드·격자 |
| `paper-cut` | `paper-layers` | 종이 무늬와 층진 윤곽 |
| `clay-toy` | `toy-island` | 둥근 모서리와 점토 재질 |
| `ink-plan` | `ink-notebook` | 해칭·선 중심의 수첩 |
| `woodblock` | `topo-outdoor` | 목판 재질 / 야외 지형도 |
| `flat-roof` | `flat-neighborhood` | 건물 높이를 시각적으로 0.07배 압축한 평면 읽기 |
| `watercolor` | `watercolor-park` | 절차 수채 패턴 |
| `manga-cel` | `evening-market` | 강한 윤곽·셀 셰이딩 / 저녁 장터 색 |
| `white-model` | `clean-architect` | 중립적인 건축 모형 |
| `realistic` | `realistic-neighborhood` | 사진을 참고한 재료·창 영역과 도시 지형 |

행은 설명용 비교다. 건물과 지도는 서로 독립적으로 조합할 수 있다. 시점 `flat`은 북쪽 고정 직교 카메라, `isometric`은 등각 직교 카메라, `perspective`는 45도 FOV의 실제 원근 카메라다. 단순 UI 이름만 바꾸는 구현이 아니다.

스타일 변경은 실제 건물 외곽선·DEM·거리·충돌·길찾기·현재 위치를 바꾸지 않는다. `flat-roof`는 명시적인 건물 시각 높이 압축이다. 지면과 기단의 고도까지 평탄화하지 않는다. 실내는 구조 예시로 유지하며 외부 건물/지도 스타일의 적용 범위는 지상이다.

사진 원장은 `research/brands/{haiver,xi,cherbo}/manifest.json`, 관찰은 같은 폴더의 `OBSERVATIONS.md`, 공식 로고는 `research/brands/official/manifest.json`이다. 이미지 URL·확인일·촬영일 확인 여부·해시를 보존한다. 공개 저장소에는 출처 원장과 관찰을 담고, 외부 조사 사진 원본과 지도 캡처는 로컬 조사 묶음으로 보관한다.

관찰에서 사용한 외형은 하이베르의 밝은 벽·석재 기단·청록 띠, 왕십리자이의 회백색 베이·주황 세로 띠·짙은 저층부, 라체르보의 밝은 세로 프레임·어두운 창 영역·크라운이다. 창 개수·로고 부착 면·기단 치수·조경 밀도는 측정값이 아닌 게임용 해석이다. 확인되지 않은 균열·해충·하자·시설 평판을 실존 단지의 사실로 넣지 않는다.

새 `public/context/*.json`에는 실제 OSM 공원·놀이터 면 23개와 라체르보 주변 지상 철도 선 30개가 있다. 하이베르9공원, 자이8공원, 라체르보4공원+2놀이터다. 작은 공원도 원본 경계를 삼각형으로 만들어 DEM 위 0.035m에 배치한다. 철도 중심선은 실제 좌표이며 침목·폭은 렌더 추정이다. 지하철 터널은 지상 선로로 그리지 않는다. 확인된 옹벽 좌표는 없어 0개다.

높낮이는 DEM 방향성 음영·고도 색·지형 경계 단면으로 잘 읽히게 했다. 코어 건물은 외곽 꼭짓점의 최고 DEM에 바닥을 두고 각 가장자리에서 지면까지 기단을 잇는다. 이 기단은 떠 보임을 막는 표현이며 실제 옹벽을 조사했다는 뜻이 아니다. 고해상도 DEM·LiDAR·실측 경사로를 확보한 상태는 아니다.

## 4. 기술스택과 선택 이유

현재 앱은 **TypeScript + Vite + Three.js + Bun**이다. 데이터 경계는 **Zod**, 아이콘은 **Lucide**, 검사 도구는 **TypeScript / Biome / Bun test**다. 스타일 실험실은 Canvas2D를 쓴다. 설치 버전은 `bun.lock`으로 고정한다.

현재 앱 자체가 Next.js나 Supabase로 작성되었다고 설명하지 않는다. 브라우저 게임 루프와 공유 공간 데이터의 독립성을 먼저 검증하기 위해 Vite를 유지했다. 사용자가 익숙한 Next.js(JavaScript)·Supabase·Python으로 옮기기 위한 경계는 다음과 같다.

- Next.js: 클라이언트 컴포넌트에서 `World`를 동적 import하고 mount 시 생성, unmount 시 `dispose`한다. `window`, `document`, WebGL 코드는 서버 컴포넌트에서 실행하지 않는다. 단지 검색·출처·상세 페이지는 서버에서 제공할 수 있다. TypeScript 런타임 코드는 JS로 변환 가능하지만 데이터 스키마 검증은 유지한다.
- Supabase: Auth, 개인 수첩/관심단지, 원천 출처·검수 상태, Storage 자산을 맡긴다. RLS로 작성자별 수첩을 격리한다. 관리자 수집 키를 브라우저에 넣지 않는다. 현재 저장소에 Supabase 키나 연결은 없다.
- 실시간 위치: 현재 Bun `/presence` WebSocket, 같은 단지·같은 방끼리 최대16명, 서버 전체64세션, IP당16세션, 최대2KB 메시지·50ms 수신 제한이다. 중앙 영속 상태나 여러 서버 간 동기화는 없다. Supabase Realtime Presence는 접속/방 정보에 쓸 수 있으나 고빈도 게임 위치는 별도 WS 또는 Colyseus 서버로 유지하는 구성이 적합하다.
- Python: 공식/API·수동 열람 자료를 정규화하고 GeoJSON/DEM→경량 셀 JSON, 이미지 출처 원장·중복/품질 검사 파이프라인을 만든다. 현재 재현 스크립트는 `scripts/*.mjs`이고 Python 파이프라인은 이전 대상이지 구현 완료가 아니다.

수익화는 광고 데모 위치만 있다. 상용 광고 SDK·추적·노출 과금·입장 전면 광고는 아직 연결하지 않았다. 기본 산책을 가리지 않는 명확한 광고 표기와 실제 광고 콘텐츠 영역을 분리해 후속 구현한다.

## 5. 폴더와 데이터 계약

- `src/controller.ts`, `main.ts`, `actions.ts`: 선택·이동모드·단지/레이어 전환·화면 동작.
- `src/scene/world.ts`: 지도·캐릭터·드라이버·입력 연결. `world-frame.ts`는 프레임 순서, `world-step.ts`는 물리/도착 동작.
- `src/scene/camera.ts`, `camera-gesture.ts`, `input.ts`: 투영·카메라·탭·핀치·이동 입력.
- `src/scene/spatial-driver.ts`, `motor.ts`, `navigation.ts`: 실제 지형 이동·충돌·경로.
- `src/world-style.ts`, `world-style-presets.ts`, `world-style-storage.ts`, `world-style-ui.ts`: 스타일 enum 계약, 프리셋, URL/저장, 선택 UI.
- `src/scene/solid-person.ts`, `styled-person.ts`, `avatar-motion.ts`: 6 메시/4 아틀라스와 거리 기반 동작.
- `src/scene/building-style.ts`, `map-style.ts`, `style-textures.ts`: 건물/지도 문법과 128px 절차 재질.
- `src/scene/terrain-relief.ts`, `neighborhood-context.ts`: DEM 기단·단면·실제 OSM 공원과 철도.
- `src/architecture/`: 공식 마크, 단지별 사진 근거 팔레트·입면 프로필.
- `src/teleport-ui.ts`, `map-teleport.ts`: 장소 목록과 지면 선택 순간이동.
- `public/worlds/`: 기존 공간 JSON, `public/context/`: 별도 주변 문맥 JSON, `public/data/`: 서울 도감·주간 관심.
- `research/`: 자료 출처와 확인 한계. `docs/`: 구현/기획 인계. `qa/`: 버전별 검사 근거.

좌표는 1단위=1m, 동쪽 +X, 남쪽 +Z다. 월드 범위는 중심에서 동서·남북650m다. 실제 높이는 Y축이다. 스타일별 좌표 복제본을 만들지 않고 같은 `SpatialWorld`를 렌더러·이동 엔진이 공유한다. 장소/지도 문자열을 HTML로 넣을 때 이스케이프하고, 외부 자료는 `src/spatial/load.ts`/Zod 경계에서 확인한다.

스타일 저장 키는 `hanbakwi-world-style-v1`이다. 스키마에 없는 URL 값, JSON 파손, 저장소 SecurityError는 기본값/안내로 처리한다. 스키마 변경 시 과거 저장값의 정규화 또는 버전 변경을 같이 설계한다.

## 6. 제작·재현 파이프라인

1. 공개 정보와 허용된 자료에서 사실·출처·확인일·불확실성을 수집한다. 새 단지는 사진10장 이상을 실제 단지 외관/공용공간으로 확인하고 조감도·개인 세대·주변 단지는 제외한다.
2. `collect-spatial.mjs`로 코어·OSM·DEM을 동일한 로컬 미터 좌표로 정규화한다. 본편은 이미 저장된 세 JSON으로 실행되므로 부팅 시 외부 지도 API 호출이 필요 없다.
3. `collect-context.mjs`로 별도 OSM 경계를 만든다. 원자료가 없는 공개 체크아웃에서는 `--refresh` 또는 `--import=/path/to/context-map.osm`로 공식 응답을 확보한다. 실패할 때 기존 결과를 지우지 않는다.
4. `profiles.ts`에 단지별 관찰 색·창 비례·브랜드 출처를 연결한다. 위치나 시설을 사진 인상만으로 추가하지 않는다.
5. 실제 ground 메시와 건물 메시를 만든 뒤 스타일을 적용한다. 좌표·경로 엔진에는 스타일 배율을 전달하지 않는다.
6. 텍스처/geometry/material은 월드 교체 시 폐기한다. 같은 팔레트의 공원은 묶고, 절차 패턴은 해당 레이어 안에서 공유한다. 60Hz 고정 물리 스텝은 배속에 따라 횟수만 늘린다.
7. 자동 검사 후 PC·모바일 브라우저에서 실제로 이동·핀치·모드·전환·도착·수첩·접속자·메모리/FPS를 확인한다. 자동 검사만 통과한 상태를 화면 완료로 표기하지 않는다.

공개 저장소는 이미 생성된 JSON과 공식 마크를 포함하므로 원자료 수집 없이 빌드·체험할 수 있다. 수집 스크립트의 재실행은 네트워크/원본 파일과 각 출처 조건이 필요하다.

## 7. 성능과 현재 한계

기본 DPR 상한은 모바일1.25·데스크톱1.5, `부드럽게` 모드는1이며 그림자를 끄고 30fps 렌더 간격을 사용한다. 기본 렌더 목표60fps, 물리 고정60Hz다. 숨은 탭은 렌더/누적을 멈춘다. 감소된 모션 설정을 따른다. HUD는 실제 측정 FPS·draw calls·삼각형 수를 표시한다.

이는 구현한 제어값이며 모든 휴대폰에서 60fps가 보장된다는 뜻은 아니다. 16배속은 최대80개 물리 스텝을 한 렌더 프레임에서 처리할 수 있어 비용이 증가한다. 고층 건물·철도·가족/peer의 메시 비용, 스타일 반복 전환 후 GPU 자원, 실제 iOS Safari·Android Chrome은 브라우저/실기 검증이 남았다.

세 가지 플레이 월드와 25개 구 도감은 서로 다른 범위다. 모든 서울 단지의 실제 외관·사진·시설·높낮이가 구현된 상태는 아니다. 실내 커뮤니티·지하 주차장은 실제 도면을 확보하지 않은 구조 예시다. 새 소문과 이슈를 실시간으로 긁어오는 수집기가 아니다. 다음 확장은 단지별 근거가 있는 셀을 추가하는 방식으로 진행한다.
